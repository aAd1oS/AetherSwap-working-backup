# AetherSwap 网络与故障排查

网络问题的首要原则是保持单一、稳定、可解释的路由。浏览器、Steam 客户端和 Python 后端可能使用不同出口，因此“网页能开”不能证明项目请求正常。

## 1. 当前 Steam 路由

桌面启动器会清理继承的 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY 及其小写变量，避免启动终端污染项目。

Steam 请求在 auto 模式下按以下优先级选择：

1. Steam 域名解析到回环地址，且本机 443 确实有监听：使用本地 Steam 反向代理；
2. 本地反向代理不可用，但项目代理池已启用：使用项目代理；
3. 两者都没有：使用系统可用路由；
4. 配置明确要求 direct：绕过环境代理。

启动日志会显示 SteamRoute：

- local_accelerator：Steam++ 等本地反向代理可用；
- project_proxy：使用项目代理池；
- system：继承系统路由；
- direct：明确直连。

BUFF、SteamDT、通知服务不必与 Steam 使用相同出口，不要把所有服务强制塞进同一个代理。

## 2. 每次启动的最小检查

1. 只保留计划使用的一条稳定网络路径；
2. 启动 AetherSwap；
3. 查看 SteamRoute；
4. 确认当前账号、地区和钱包币种；
5. 查看阻塞订单；
6. 只执行一次同步入库或刷新现价；
7. 成功后再启动购买任务。

旧版“四项服务自检”已删除。它会制造额外请求，而且普通 HTTP 状态不能证明登录和真实业务接口可用。

## 3. Steam++ 是否真的接管

进程存在或界面打开不代表加速服务可用。检查：

    Resolve-DnsName steamcommunity.com
    netstat -ano -p tcp | Select-String ":443"

只有 Steam 域名解析到回环地址且 443 端口存在监听时，项目才会选择本地反向代理。

如果 DNS 指向 127.0.0.1 但 443 没有监听，通常是残留 Hosts/DNS。先使用原工具的网络恢复功能，不要绕过证书警告。

## 4. 常见错误

| 现象 | 常见含义 | 应对 |
|---|---|---|
| ERR_CERT_COMMON_NAME_INVALID | 域名被错误指向本地服务或代理证书不匹配 | 不输入密码；检查 DNS、Hosts 和 443 监听 |
| 10054 / 10053 | 对端或中间网络重置连接 | 停止任务，保持单一路由，重启后只验证一个业务动作 |
| ConnectTimeout | 路由、DNS、代理或目标服务未及时响应 | 不无限延长超时；重建稳定 Session |
| HTTP 429 | 当前 IP、Cookie 或请求模式受到限流 | 停止刷新和验证，保留 Cookie，等待后低频复查 |
| HTTP 401 / 登录页 | 鉴权失效或账号不一致 | 用项目浏览器重新登录，只验证一次 |
| TooManyRedirects / JWT 循环 | Steam SSO 或本地反向代理链异常 | 使用有界诊断，不把 302 当成功，不无限跟随 |
| BUFF 未携带 session | Cookie 不完整或失效 | 重新登录并保存完整 Cookie |
| BUFF Action Forbidden | 平台风控或权限限制 | 停止请求，不通过换 IP 高频撞接口 |
| SteamDT/iFlow 失败 | 候选数据源异常 | 不通过重新登录 Steam 解决 |

429 不应自动转换为 Cookie 过期。等待期间反复验证、刷新库存和历史价格可能延长限流。

## 5. DNS、Hosts 和证书

检查：

    Resolve-DnsName store.steampowered.com
    Resolve-DnsName steamcommunity.com
    Get-Content "$env:SystemRoot\System32\drivers\etc\hosts" |
      Select-String "steam"

修改 Hosts 前必须确认条目来源并保留完整备份。修改后可刷新 DNS：

    ipconfig /flushdns

不要使用 docs 中的历史 hosts 文件恢复系统；该文件已从项目文档中移除。

## 6. 浏览器正常但程序失败

记录以下事实：

- 浏览器请求域名和 HTTP 状态；
- 项目日志中的 route、host、状态码和异常类型；
- DNS 是否解析到回环地址；
- 项目代理池是否启用；
- 错误前是否刚切换代理、节点或 Steam++。

浏览器扩展可能只代理浏览器；启动器也会清理环境代理，所以两者不一致是正常排查方向。

## 7. Steam 登录与 JWT 诊断

账号验证使用有界重定向和市场页面证据；跨站、循环或无法识别的结果保持 unavailable，不删除 Cookie、不自动密码重登。

持续出现 JWT 循环时，关闭 AetherSwap 后只运行一次：

    diagnose-steam-auth-flow.cmd

诊断最多执行有限只读请求，只记录 Cookie 名称、Set-Cookie 元数据和查询参数名称，不记录值或响应正文。历史专项结论见 [archive/2026-08-06至12_早期安全与认证审查](archive/2026-08-06至12_早期安全与认证审查.md)。

## 8. 钱包、库存和 BUFF

- 钱包币种同步失败会暂停自动出售，这是安全行为；
- Steam 库存 403、429 或暂时不可用不应直接触发高频重登；
- BUFF 人机验证和 Action Forbidden 需要人工恢复；
- 收货失败时分别核对订单是否付款、卖家是否发货、Steam 是否收到报价、本地台账是否有平台订单号；
- 不连续点击余额、库存、现价和账号验证刷新。

## 9. 最小排查模板

1. 记录时间和当前网络路径；
2. 启动一个新进程，不启动购买；
3. 查看钱包/地区同步和 SteamRoute；
4. 手动验证一个业务功能；
5. 导出对应时间段的脱敏日志；
6. 失败后停止，不同时改变 Cookie、代理和 DNS。

向维护者提供：时间、异常类型、HTTP 状态、路由、浏览器同域状态和 DNS 结果。不要提供 Cookie、Token、密码、.maFile 或邮箱授权码。
