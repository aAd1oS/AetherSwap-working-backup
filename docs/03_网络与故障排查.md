# AetherSwap 网络与故障排查

适用目录：`D:\Vibe Coding\steam`

本手册只说明当前本机版本。网络环境随节点、运营商、Steam 和 BUFF 风控变化，不存在一个对所有时间都有效的“必开工具”。最重要的是保持单一、稳定、可解释的路由。

## 1. 当前路由逻辑

### 桌面启动器

`start-aetherswap-desktop.cmd`启动前会清空当前进程继承的：

- `HTTP_PROXY`
- `HTTPS_PROXY`
- `ALL_PROXY`
- 对应的小写环境变量

这样可以避免 Codex、浏览器或其他终端代理变量意外污染 AetherSwap。

### Steam 请求优先级

项目当前按以下优先级建立 Steam Session：

1. 项目代理池已启用：使用项目配置的代理。
2. 未启用代理池，但 Steam 域名解析到本机回环地址：认为存在本地 Steam 反向代理，并忽略环境变量代理。
3. 两者都没有：继承当前系统能够提供的网络路由。

项目不会因为一次失败就把 Cookie 自动判为过期；`429`和暂时不可用应保留为网络/限流状态。

### BUFF 和国内数据源

BUFF、SteamDT/iFlow、PushPlus 不一定需要与 Steam 使用相同出口。不要仅因为 Steam 需要特殊网络，就强制把所有服务塞进同一代理池。

### 当前本机代理池

整理文档时，项目代理池为关闭状态且没有配置代理。后续如果修改，以页面实际配置和日志中的 `ProxyManager`为准。

## 2. 推荐运行原则

- 使用已经验证能完成真实购买的稳定网络路径。
- 任务运行期间不要频繁换节点、开关系统代理或叠加多套网络工具。
- 浏览器能打开网页，只能证明浏览器路径可用；Python 后端可能使用不同路由。
- Steam 客户端能连接，也不能证明 AetherSwap 的 HTTPS 请求可用。
- 出现问题时一次只改变一个变量，并记录改变前后的日志。
- 不要使用大量免费公共代理处理主账号和交易 Cookie。

## 3. 不再使用“四项服务自检”

旧版页面曾有 Steam Community、Steam Store、BUFF、SteamDT 四项 HTTP 自检。该功能已经删除，原因包括：

- 自检本身会产生额外真实请求。
- 普通 HTTP 状态不能代表账号已登录。
- `429`期间反复自检会延长限流。
- 自检路径与真实市场、订单、历史价格请求不完全相同。

现在使用真实但低频的业务动作验证：

1. 账号管理验证 Steam Cookie。
2. 查看订单台账和钱包同步日志。
3. 手动“刷新库存”。
4. 手动“刷新商品现价”。
5. 查看明确的失败接口和 HTTP 状态。

不要连续点击刷新。每次失败后先读日志。

## 4. 每次启动的最小检查

1. 启动当前计划使用的单一稳定网络路径。
2. 不要同时切换多个加速、代理或本地反向代理工具。
3. 双击 `start-aetherswap-desktop.cmd`。
4. 查看启动日志中的代理池状态。
5. 确认账号地区和钱包币种同步成功。
6. 查看订单台账是否存在未决订单。
7. 先执行一次“同步入库状态”或“刷新商品现价”。
8. 成功后再启动购买任务。

## 5. 浏览器正常但程序失败

这是常见情况，可能原因：

- 浏览器扩展或系统代理只接管浏览器。
- AetherSwap 启动器清理了代理环境变量。
- Steam 域名被本地 Hosts 或反向代理改写。
- 浏览器和 Python 使用不同 DNS、Cookie 或出口 IP。
- 浏览器请求频率低，而程序短时间访问多个市场接口。

排查时记录：

- 浏览器 Request URL 和 HTTP 状态。
- Python 日志中的 host、route、HTTP 状态或异常类型。
- `Resolve-DnsName`结果。
- 项目代理池是否启用。

## 6. DNS 与 Hosts

检查 DNS：

```powershell
Resolve-DnsName store.steampowered.com
Resolve-DnsName steamcommunity.com
```

检查 Hosts：

```powershell
Get-Content "$env:SystemRoot\System32\drivers\etc\hosts" |
  Select-String "steam"
```

### 解析到 `127.0.0.1`

分两种情况：

- 本地 Steam 反向代理正在运行并监听对应端口：可能是正常设计。
- 没有任何本地代理服务运行，但 Hosts 或 DNS 仍指向 `127.0.0.1`：Steam 会连接到错误服务，常见结果是证书域名不匹配或连接失败。

不要直接删除自己不理解的 Hosts 条目。先确认是谁创建的，并保留原文件副本。

修改后刷新 DNS：

```powershell
ipconfig /flushdns
```

## 7. `ERR_CERT_COMMON_NAME_INVALID`

含义：浏览器收到的证书不属于当前 Steam 域名。

常见原因：

- Steam 域名被错误映射到 `127.0.0.1`。
- 本地反向代理没有运行，但 Hosts 重定向仍存在。
- HTTPS 扫描、证书代理或多个网络工具互相干扰。

处理：

1. 不要在警告页面输入密码。
2. 检查 DNS 和 Hosts。
3. 确认本地代理是否实际运行。
4. 暂时只保留一种网络路径。
5. 修复后重新打开浏览器，不要绕过证书警告。

## 8. `10054`、`10053` 和连接中止

典型日志：

```text
ConnectionResetError(10054, 远程主机强迫关闭了一个现有的连接)
ConnectionAbortedError(10053, 本机软件中止了一个已建立的连接)
```

可能原因：

- 目标服务器或中间网络重置连接。
- Python 后端没有走浏览器使用的网络路径。
- 节点、系统代理、本地代理或安全软件中途切换连接。
- Steam 对当前出口或请求模式不稳定。

处理顺序：

1. 停止购买任务。
2. 保持当前网络工具不再切换。
3. 用浏览器打开同一 Steam Community 域名。
4. 检查项目日志中的 route。
5. 重新启动 AetherSwap，使 Session 使用稳定的新路由。
6. 只做一次“刷新商品现价”验证。

连续两次仍失败就停止测试，不要批量刷新 25 个候选商品。

## 9. `ConnectTimeout` 或 `Max retries exceeded`

超时说明连接没有在规定时间完成，不等于 Cookie 失效。

处理：

- 检查域名是否能解析。
- 检查浏览器是否能打开同一域名。
- 确认项目代理池没有启用空代理或失效代理。
- 避免在网络切换过程中保留旧进程。
- 停止任务后重启桌面版，让 Session 重新建立。

不要同时把超时时间无限加长；超长等待只会让一个候选检查卡住几分钟。

## 10. Steam `HTTP 429`

`429`表示请求过多或当前出口受到限流。它可能按 IP、接口、Cookie、请求特征或组合维度生效。

出现后：

1. 停止购买任务。
2. 不要重复账号验证、刷新库存、刷新历史价格或四处换 Cookie。
3. 不要把 `429`当成密码错误。
4. 保持 Cookie，不触发自动重新登录。
5. 等待冷却后只做一次低频业务请求。

恢复时间没有固定保证。网上的 10 到 15 分钟只是个别经验；持续数小时甚至更久也可能发生。等待期间频繁验证会重新产生请求。

当前代码已有的低影响保护包括：

- 全局节流和请求间隔。
- 候选检查连续失败后暂停本轮。
- 历史接口限流后停止继续检查。
- `429`不会自动转换成 Cookie 过期。
- 缓存和同名商品请求合并。

旧“429 待实施方案”已经删除；本文件只记录当前行为和后续仍需改进的部分。

### **经验之谈：网络引起的429概率不小，故检查完全部网络后还不行才认定为达到限流**



## 11. Steam `HTTP 401`、未登录或 Cookie 过期

`401`通常与鉴权有关，但必须结合具体接口判断。

处理：

1. 在账号管理查看当前账号。
2. 使用项目浏览器完成一次正常登录。
3. 保存新 Cookie。
4. 只点击一次验证。
5. 确认 Steam ID 与 Cookie 对应同一账号。

如果市场页面显示未登录，而 Store 登录正常，可能是 Cookie 域、字段或 Session 使用方式不完整，不要仅根据浏览器首页头像判断。

## 12. Steam 钱包信息错误

典型日志：

```text
Steam 社区市场未返回钱包信息
Steam 钱包 API HTTP 401/404
无法获取 Steam 钱包余额
```

检查：

- Cookie 是否来自目标账号。
- 账号是否已经设置 Steam 钱包币种。
- 市场页面是否真实登录。
- 当前是否存在 `429`或网络超时。
- Store、Community 和 API 是否走了互相冲突的出口。

钱包同步失败会暂停自动出售安全许可，避免币种不明时错误定价。这是保护行为，不应通过删除校验绕过。

## 13. BUFF 错误

### `未携带 session`

重新登录 BUFF 并保存完整 Cookie。

### `Action Forbidden`

停止请求并查看 BUFF 账号通知或联系客服。不要通过高频换 IP 继续撞接口。

### 人机验证或页面过期

停止任务，在正常浏览器完成验证，然后再保存 Cookie。一次完成后不要连续刷新验证接口。

### 收货失败

分别检查：

- BUFF 订单是否已支付。
- 卖家是否已发货。
- Steam 是否收到交易报价。
- 报价中的账号和物品是否正确。
- 本地订单台账是否记录了对应平台订单号。

## 14. SteamDT/iFlow 失败

SteamDT/iFlow 是候选数据源，不是 Steam 登录服务。其失败时：

- 检查普通网页是否能访问。
- 查看接口是否返回数据或结构发生变化。
- 不要通过重新登录 Steam 解决。
- 不要连续启动任务制造重复拉取。

## 15. 最小化排查模板

每轮只做以下动作：

1. 记录当前网络路径和时间。
2. 启动一个新的 AetherSwap 进程。
3. 不启动购买任务。
4. 查看钱包/地区同步日志。
5. 手动刷新一个业务功能。
6. 导出对应日志。
7. 失败后停止，不立即更换三个变量重试。

向 Codex 提问时提供：

- 错误发生时间。
- 完整异常类型和 HTTP 状态。
- 当时项目代理池状态。
- 浏览器同域名是否可访问。
- DNS 是否解析到 `127.0.0.1`。
- 发生错误前是否刚切换网络路径。

不要提供 Cookie、Token、密码、`.maFile` 或邮箱授权码。
