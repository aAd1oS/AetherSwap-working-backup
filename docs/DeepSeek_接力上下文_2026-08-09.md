## 2. 当前项目是什么

AetherSwap是本地运行的Steam/BUFF饰品交易辅助工具。当前主要流程是：

```text
SteamDT获取候选
  -> 本地候选过滤和流动性保护
  -> BUFF与Steam价格/卖单/历史稳定性预检
  -> BUFF锁单与付款
  -> Steam报价接收和库存同步
  -> 交易冷却
  -> 按出售策略上架Steam市场
```

本地入口：

- 桌面启动器：`start-aetherswap-desktop.cmd`
- 服务端启动器：`start-aetherswap-server.cmd`
- 本地地址：`http://127.0.0.1:28472/`
- Python虚拟环境：`.venv`

## 4. 已完成的重要改进

### Steam和BUFF稳定性

- 区分Cookie过期、429限流和暂时不可用。
- Steam历史价格与卖单请求有节流和网络保护。
- BUFF具有请求间隔、缓存、429暂停、普通网络失败暂停和恢复模式候选上限。
- 当前已能稳定完成真实小额购买；不要无专项理由重写网络路由。

### 资金与订单

- 今日投入、未决占用和剩余额度可持久统计。
- 未决付款或待核对订单阻止继续锁单。
- BUFF余额支付先写平台订单台账，再最多支付一次；结果未知时停止并要求人工核对。
- 支持“旧单取消，新单已付款”的替代订单补录。
- 有单件最高购买价硬保护。

### 候选流动性

- SteamDT请求携带 `min_volume`，本地再次硬校验 `transactionCount`。
- 默认门槛为200；缺失、异常或低于门槛的数据在网络预检前拒绝。
- 本地过滤和冷却排除后才按SteamDT原始排名截取候选。
- 单轮候选冷却池只保存本轮真正进入预检的 `goods_id`；下一轮排除，再下一轮解除。
- 正常候选上限30，BUFF恢复模式上限10，不增加HTTP请求。

### 界面与运维

- 日志可选择复制，关键业务成功使用绿色。
- 每轮retry前输出并可导出轮次总结。
- 可手动刷新库存、商品现价、持有信息和BUFF余额。
- 提供安全GitHub上传脚本：`upload-safe-backup-to-github.cmd`。

## 5. 当前仍需关注的高价值问题

以下是待办或需要真实样例的问题，不代表已经证实会造成损失：

1. **自动Steam确认范围过宽**：配置 `device_id` 后，现有逻辑可能确认全部待确认项。自动出售前应改成只确认本轮指定资产。不要把“补上device_id”当作修复。
2. **Steam上架价格字段语义待真实验证**：当前价格可能是在把买家显示总价反算为卖家到手价。直接改公式可能反而错误，必须用低价值真实上架样例核对买家支付和卖家收到。
3. **普通扫码支付路径的未知结果重试**：当前主要使用余额支付，风险路径通常不触发；扩大使用支付宝/微信手动回退前应专项复核。
4. **订单与数据库约束**：平台事实核对、合法状态迁移、唯一约束和并发事务仍可继续加强。
5. **出售前安全确认**：首批真实冷却商品到期后，应先做低价值预览和人工确认。
6. **本地秘密保护**：Cookie和Token主要依赖本地文件权限与忽略规则，未来可评估Windows DPAPI或Credential Manager。
