# AetherSwap 后续改进建议

本文件记录当前版本已经完成的改进、仍存在的边界和推荐开发顺序。它不是承诺，也不代表所有功能都应一次实现。

原则：优先保护真实资金和订单一致性，其次改善操作体验；已经跑通的 Steam/BUFF 网络路由应尽量保持稳定，涉及底层网络时先说明影响并做离线测试。

## 1. 已完成的关键改进

### Steam 和 BUFF 稳定性

- Steam Session 能识别项目代理池、系统路由和本地 Steam 反向代理。
- 本地反向代理存在时避免继承错误的环境变量代理。
- 钱包币种同步失败时暂停自动出售。
- `429`、暂时不可用和 Cookie 过期不再混为同一种状态。
- Steam 历史价格和卖单请求有节流、失败暂停和低频保护。
- BUFF 请求具备基础节流、缓存和熔断保护。

### 购买资金保护

- 今日投入额度跨程序重启保留。
- 手动添加记录不占自动购买额度。
- 待支付和付款待核对订单占用额度。
- 未决支付订单会阻止继续锁单。
- 平台订单号在付款入口展示前写入数据库。

### 订单与库存

- 新增持久化订单台账。
- 记录订单号、数量、金额、状态和错误说明。
- 记录入库时间、`assetid`和交易冷却时间。
- 新增“同步入库状态”“刷新商品现价”“刷新全部持有信息”。
- 当前商品价格和更新时间写入数据库。
- 手动刷新库存不会触发自动出售。
- 新增“旧单取消，新单已付款”，以单一事务取消旧单、创建替代订单和购买记录；新平台订单号具备重复保护并计入今日额度。
- 收货状态明确区分“待卖家发送报价”和“报价已发送，待在 Steam 接受”。
- 手动接受报价后，“同步入库状态”会复用已经取得的库存快照补全 `assetid`、入库时间、冷却时间和订单状态，不增加额外网络请求。
- 同名商品只有在名称、数量和未占用 `assetid` 能唯一对应时才自动补录；歧义情况保留人工处理。
- 替代订单可由用户选择读取当前 Steam 市场价并写作补录时的购入市场价；请求失败时不会写入半条订单。

### 界面和排障

- 运行日志可鼠标选择和复制。
- 删除会产生额外请求且容易误导的四项服务自检。
- 页面显示今日额度、已确认投入、未决占用和剩余额度。

## 2. P0：订单真实性与资金一致性

这是下一阶段最值得优先投入的部分。

### 2.1 平台订单状态核对

当前订单台账能够持久化本地状态，并根据本地购买、入库、上架和出售记录推进状态，但“用户点击已付款”与“BUFF 平台确认支付”仍不是完全相同的事实。

目前已能安全登记“旧单取消后在 BUFF 重新购买”的人工事实，但新订单号和付款结果仍来自用户输入，尚未由 BUFF 平台接口自动核验。

建议：

- 使用明确的 BUFF 订单查询接口核对订单状态。
- 区分用户确认、平台已支付、卖家已发货、平台退款。
- 只在平台事实明确后释放未决占用。
- 无法查询时保持“需要人工处理”，不自动猜测。

验收：程序崩溃、重启或用户重复点击后，同一个平台订单不会产生第二次购买责任。

### 2.2 支付入口恢复

当前重启后能恢复订单阻断，但出于安全和实现范围，付款链接未作为完整可恢复凭证持久化。

建议：

- 评估付款链接的有效期和敏感性。
- 只保存可安全恢复的订单定位信息。
- 重启后通过平台订单重新获取处理入口，而不是永久保存敏感 URL。

### 2.3 数据库约束

建议增加：

- 平台订单号唯一约束的迁移测试。
- 购买记录与订单记录的外键或明确关联约束。
- 同一 `assetid`不能同时属于两条活跃持有记录。
- 状态只能按合法状态机迁移。
- 数据库写入使用事务，避免订单成功但购买记录只写入一半。

## 3. P0：出售前安全确认

购买链路稳定后，真实资金风险会转移到自动出售。

建议：

- 第一次自动上架必须展示预览并人工确认。
- 显示购买成本、当前价、预计上架价、Steam 手续费和预计到账。
- 上架价偏离当前市场参考价过大时阻止执行。
- 同一批次设置最大自动上架数量。
- 明确显示本地购买记录与库存 `assetid`的匹配依据。
- 任何匹配不确定的个人库存都跳过。

验收：模拟运行和真实运行使用同一套定价输出，真实上架前能看到最终价格与原因。

## 4. P1：手动刷新体验

当前已经有三个手动刷新入口，下一步可以提高可见性和降低请求量。

建议：

- 每个商品显示最后成功刷新时间。
- 支持勾选部分商品刷新现价。
- 同名商品请求继续合并。
- 正在自动刷新时，手动刷新复用同一任务而不是并发请求。
- 返回成功、缓存命中、失败和限流数量。
- 明确区分“只刷新”“接受交易报价”“触发出售”三种副作用。

验收：快速重复点击不会产生第二批相同请求，页面能说明哪些价格仍是旧缓存。

## 5. P1：只读运行模式

增加全局“只读模式”：

- 允许登录验证、查看订单、刷新库存和价格。
- 禁止 BUFF 锁单、付款确认、接受报价、Steam 上架和确认。
- 页面顶部持续显示只读状态。
- 每个被禁止的动作返回明确原因。

这能用于网络排查、新账号配置和策略验证，减少误操作风险。

## 6. P1：安全备份与 GitHub

建议新增 Windows 一键脚本：

1. 检查 AetherSwap 是否已经停止。
2. 复制允许上传的源码文件。
3. 排除配置、数据库、日志、`.venv`、`.playwright`和浏览器资料。
4. 搜索常见凭证键和值特征。
5. 生成文件清单和 SHA256。
6. 可选提交到指定私有 GitHub 仓库。

脚本必须默认只创建新目录，不覆盖旧备份，也不自动删除失败备份。

## 7. P1：本地秘密保护

当前凭证主要依赖本地文件权限和 `.gitignore`。

建议：

- 使用 Windows DPAPI 或 Credential Manager 加密 Token、Cookie 和密钥。
- 页面默认隐藏敏感字段，只允许显式短时显示。
- 日志统一脱敏 Cookie、Token、代理密码和付款 URL。
- 配置导出默认不包含秘密，另设加密凭证备份流程。

验收：把整个源码目录复制给别人时，对方无法从普通文本恢复账号凭证。

## 8. P2：订单中心

将当前订单台账扩展成完整订单中心：

- 按状态、日期、商品和平台订单号筛选。
- 展示状态时间线。
- 提供“重新核对平台状态”，不直接修改成成功。
- 支持导出不含凭证的 CSV。
- 显示每笔订单占用的今日额度。
- 标记人工修正并记录修改原因。

## 9. P2：策略可解释性

目前日志能看到部分筛选原因，但小白仍难以判断为什么某件商品被选择或跳过。

建议：

- 为每个候选生成决策摘要。
- 显示 BUFF 参考价、Steam 深度价、历史稳定性和最终安全上限。
- 把“硬性拒绝”和“数据暂不可用”分开。
- 在策略模拟中显示参数变化前后的候选差异。
- 保存策略版本，允许回滚到上一次实盘配置。

## 10. P2：缓存式运行健康状态

不恢复旧四项网络自检。可以增加不产生真实请求的状态页，只读取现有运行数据：

- 最近一次 Steam 成功请求时间。
- 最近一次 BUFF 成功请求时间。
- 当前 Session 路由类型。
- 最近一次 `429`、超时或鉴权失败。
- 当前冷却剩余时间。
- Cookie 最近一次验证结果。

只有用户明确点击具体业务刷新时才产生真实请求。

## 11. P2：出售后对账

建议：

- 从 Steam 市场历史核对真实成交金额。
- 区分展示价格、买家支付金额和卖家到账金额。
- 记录 Steam 手续费。
- 核对已售出商品是否从活跃库存和在售列表消失。
- 对“在售列表消失但历史中未找到成交”的情况标记人工处理。

## 12. 不建议近期做的改动

- 为解决偶发网络问题重写全部 Steam Session。
- 自动轮换大量公共代理规避 `429`。
- 同时接入多个新的购买和出售平台。
- 在订单状态机稳定前扩大自动付款范围。
- 把管理面板暴露公网。
- 把任意 Python 代码执行开放给策略模块。

## 13. 推荐实施顺序

1. BUFF 平台订单状态真实性核对。
2. 数据库事务、唯一约束和合法状态迁移。
3. 第一次自动上架预览与价格偏差保护。
4. 只读运行模式。
5. 手动刷新去重、部分刷新和更新时间展示。
6. 一键安全备份与凭证扫描。
7. DPAPI/Credential Manager 本地秘密保护。
8. 完整订单中心和出售后对账。
9. 策略解释与版本回滚。

每一阶段都应先用模拟数据和离线测试验证，再进行小额真实测试。涉及 Steam/BUFF 底层网络的修改应单独说明，不与界面或文档重构混在同一批次。
