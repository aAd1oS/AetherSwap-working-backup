# AetherSwap 账号配置与首次交易

本文用于账号已经满足 Steam/BUFF 正常交易条件、准备完成第一次小额闭环的情况。

如果只是第一次打开程序，请先完成 [空白安装验收](01_安装与日常使用.md)，不要直接开始本页的真实购买步骤。所有配置使用你自己的账号；不导入维护者数据库或完整配置。本项目不会替你开通平台市场权限或绕过等待期。

## 1. 资金流与边界

当前默认闭环是：

    人民币或支付账户
      -> BUFF 购买饰品
      -> Steam 报价入库
      -> 交易保护期
      -> Steam 社区市场出售
      -> Steam 钱包余额

Steam 钱包余额通常不能由 Steam 官方直接提现。项目显示的“变现收益”只是按配置比例折算的理论现金等价，不是已经到账的现金。

## 2. 必须保护的凭据

以下内容不得截图、发群、写入 Markdown、日志或提交到 Git：

- Steam 密码与 Cookie；
- BUFF Cookie 和 session；
- shared_secret、identity_secret、device_id；
- .maFile；
- 邮箱 IMAP 授权码；
- Lark Webhook、PushPlus Token；
- C5 app-key；
- 代理账号和密码。

完整配置导出和 config/app.db 同样属于敏感文件。

## 3. 账号选择

新账号隔离性更好，但可能受 Steam Guard、充值、好友、市场和交易保护限制。常用大号限制较少，但凭据泄露或错误出售的影响更大。

无论使用哪个账号：

- 不绕过平台等待期或风控；
- 第一次只做低价值闭环；
- 大号默认关闭自动出售；
- 先刷新库存，确认个人物品均为“个人保护”。

## 4. Steam 与 BUFF 配置

### Steam

1. 添加账号并设为当前账号；
2. 按实际登录方式完成 Steam Guard 验证；需要程序生成验证码时才配置该账号自己的 shared_secret；
3. 首次使用保持自动确认关闭；确需自动确认时再配置 identity_secret 和设备信息，不从他人处获取密钥；
4. 点击“更新 Steam 信息”，在项目浏览器中完成登录；
5. 返回页面保存 Cookie；
6. 只点击一次“验证”；
7. 确认页面显示的 SteamID、账号和钱包币种一致。

“更新 Steam 信息”负责登录和保存；“验证”只检查现有状态。302、429 或网络暂时不可用不应自动转换成 Cookie 过期。

### BUFF

1. 在正常浏览器或 App 完成登录、实名和 Steam 绑定；
2. 用项目浏览器登录或手动保存完整 Cookie；
3. 确认 BUFF 绑定的是同一个目标 Steam 账号；
4. 只做一次低频读取验证。

出现“未携带 session”、Action Forbidden、人机验证或平台限制时停止任务，不要高频重试或批量切换代理。

## 5. 多账号切换

当前账号凭据、购买、订单、库存归属和出售记录按账号隔离。切换前必须：

1. 停止购买任务；
2. 处理完待支付和待核对订单；
3. 等待库存、收货、在售同步等账号操作结束；
4. 切换后重新检查 Cookie、令牌、SteamID 和钱包币种；
5. 新账号重新登录，不继承旧账号凭据。

系统仍按单实例、单当前账号设计，不支持在同一实例中并发运行两个账号。

首次配置时不要批量添加账号。新账号不应继承维护者的身份、资金、库存或授权；发现这类数据即停止安装并联系维护者。

## 6. 通知

Lark 和 PushPlus 二选一即可；同时配置时优先 Lark，失败后回退 PushPlus。通知必须能覆盖：

- 待人工付款；
- 付款或锁单结果未知；
- 报价无法唯一匹配；
- Steam 上架待确认超时；
- 长时间在售复评或需要人工处理。

通知不能代替平台页面核对。

## 7. 第一次交易前检查

账号：

- [ ] Steam Guard 和市场权限正常；
- [ ] Steam 与 BUFF 是同一目标账号；
- [ ] Cookie、令牌和钱包币种检查通过；
- [ ] 通知已测试可达。

程序：

- [ ] 订单台账没有阻塞状态；
- [ ] 自动出售范围已经理解；
- [ ] 当前策略保守；
- [ ] 单件最高购买价和今日投入额度足够小；
- [ ] 日志没有持续网络错误。

资金：

- [ ] 即使全部损失也不影响生活；
- [ ] 不以“必须花完预算”为目标；
- [ ] 第一次余额自动扣款全程观察 BUFF 订单页。

## 8. 今日投入额度

target_balance 表示当天自动任务的投入上限：

- 已确认自动购买计入额度；
- 待支付和付款待核对订单预占额度；
- 程序重启不会清零；
- 本地日期变化后进入新一天；
- 手动补录不占自动额度，但仍应纳入人工风险判断。

## 9. 第一次购买

1. 打开操作记录，确认没有阻塞订单；
2. 同步入库状态并刷新一次现价；
3. 启动购买任务；
4. 观察 SteamDT、BUFF 和 Steam 预检日志；
5. 人工支付时核对商品、数量、单价、总价和平台订单号；
6. 付款后点击与该订单绑定的确认入口；
7. 等待平台状态进入已支付、待发货或待接收报价；
8. 第一笔状态未明确前不得再次启动任务。

余额自动支付会先写订单台账，再至多主动支付一次。锁单或扣款结果未知时，系统应保留阻断订单并停止，不得自动重试。

## 10. 未决订单

待支付、用户已确认但平台未核对、付款结果未知和需要人工处理都会阻止新锁单。

处理顺序：

1. 按平台订单号打开 BUFF 订单页；
2. 已付款则等待后续状态，不解除阻断；
3. 只有平台明确未支付、已取消或已退款，才在本地确认取消；
4. 本地按钮不会替你取消平台订单；
5. 旧单取消后重新购买，使用“旧单取消，新单已付款”原子补录入口。

## 11. 入库、冷却和出售

付款后等待卖家发送 Steam 报价。同步入库会尝试按账号、状态、商品和数量唯一匹配；无法唯一匹配时转人工，不按名称猜测。

入库后检查 assetid、库存归属和交易保护时间。存在冷却说明但无法解析时，系统应保持不可交易、不可出售。

第一次上架前确认：

- 商品确实属于当前账号的 AetherSwap 购入记录；
- assetid 唯一且为自动托管；
- 冷却结束；
- 市场价、策略价、手续费估算和成本底线合理；
- Steam 手机确认列表中没有与本轮无关的操作。

待 Steam 确认的上架会保持 pending_confirmation，不应重复规划；超过 30 分钟仍未被在售同步识别时会提醒人工核对。

## 12. 立即停止的情况

- 商品、数量、价格或账号与页面不一致；
- 平台提示安全警告、异常登录或交易受限；
- 订单、付款、报价或确认结果不明确；
- Cookie、Token 或密钥疑似泄露；
- 连续出现 429、证书错误、10054 或大量超时；
- 自动出售涉及个人库存；
- 同一资产疑似重复记录、重复上架或无法唯一匹配。

先停止、保存脱敏日志并核对平台事实，再决定是否继续。

停止购买按钮不保证全部后台活动停止。需要完整退出时在启动终端按 Ctrl+C，确认本机页面不再可访问；单纯关闭网页或桌面窗口不等于退出。
