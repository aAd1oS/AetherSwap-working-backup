# AetherSwap 安装与日常使用

适用环境：Windows 10/11，本地目录 `D:\Vibe Coding\steam`。

这份文档同时覆盖本机复现、第一次启动和每天使用。已经安装完成的人可以直接从“日常启动”开始。

## 1. 项目是做什么的

AetherSwap 当前主要流程是：

1. 从 SteamDT/iFlow 获取候选饰品数据。
2. 检查 BUFF 实时卖单、Steam 市场深度和历史价格。
3. 在 BUFF 锁单并等待用户付款。
4. 收取 BUFF 卖家发来的 Steam 交易报价。
5. 等待 Steam 交易冷却结束。
6. 按启用的出售策略上架 Steam 社区市场。
7. 在数据库和页面中记录成本、现价、状态及出售结果。

它不是无风险套利工具。价格、平台限制、交易冷却、卖家发货和网络状况都可能造成损失或延迟。

## 2. 本机已经具备的环境

当前项目包含：

- `.venv`：Python 虚拟环境。
- `.playwright`：本地 Chromium、无头浏览器和 FFmpeg 运行文件。
- `.agreed_disclaimer`：已确认本地免责声明。
- `start-aetherswap-desktop.cmd`：推荐启动方式。
- `start-aetherswap-server.cmd`：只打开本地 Web 服务的备用方式。
- `config/app.db`：交易和订单数据库。

`.venv` 和 `.playwright` 都可以重新生成，不应该上传 GitHub。

## 3. 从零安装

### 3.1 准备软件

安装以下软件：

- Python 3.10 或更高版本。
- Git。
- Chrome 或 Edge。
- Steam 客户端。

在 PowerShell 中检查：

```powershell
python --version
git --version
```

### 3.2 克隆项目

新安装时执行：

```powershell
cd "D:\Vibe Coding"
git clone https://github.com/VexedWilosn/AetherSwap.git steam
cd "D:\Vibe Coding\steam"
```

如果 GitHub 的 Windows TLS 出现 `Schannel` 或 `SEC_E_NO_CREDENTIALS`，可以只对本次克隆使用 OpenSSL：

```powershell
git -c http.sslBackend=openssl clone https://github.com/VexedWilosn/AetherSwap.git steam
```

不要为了修复克隆问题长期关闭证书校验。

### 3.3 创建虚拟环境

```powershell
cd "D:\Vibe Coding\steam"
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

若 PowerShell 阻止激活，可在当前窗口临时放行：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

### 3.4 安装依赖

```powershell
python -m pip install --upgrade pip
python -m pip install --no-cache-dir -r requirements.txt
python -m pip install pytest
```

如果提示 `cannot import name 'Sentinel' from typing_extensions`：

```powershell
python -m pip install --upgrade typing_extensions
```

### 3.5 安装 Playwright 浏览器

将浏览器固定到项目目录：

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "D:\Vibe Coding\steam\.playwright"
python -m playwright install chromium
python -m playwright install --list
```

能看到 Chromium、headless shell、FFmpeg 和 winldd 即表示安装成功。

## 4. 日常启动

### 4.1 推荐：桌面模式

双击：

```text
D:\Vibe Coding\steam\start-aetherswap-desktop.cmd
```

桌面启动器会：

- 固定工作目录。
- 使用项目内 `.venv` 和 `.playwright`。
- 监听 `127.0.0.1:28472`。
- 清理启动终端继承的 `HTTP_PROXY`、`HTTPS_PROXY` 等环境变量。
- 打开 AetherSwap 桌面窗口。

不要直接双击 `run.py`，否则可能使用错误的 Python、浏览器路径或代理环境变量。

### 4.2 备用：本地服务器模式

双击：

```text
D:\Vibe Coding\steam\start-aetherswap-server.cmd
```

然后在浏览器打开：

```text
http://127.0.0.1:28472/
```

服务器模式不会自动弹出内嵌登录窗口时，可使用页面提供的“打开浏览器”或手动 Cookie 流程。

### 4.3 判断启动成功

满足以下条件即可：

- 页面能打开并显示 AetherSwap。
- 仪表盘状态能刷新。
- 账号管理能显示已经保存的账号。
- 日志没有持续重复的启动异常。

启动成功不等于 Steam、BUFF 已登录，也不等于可以立即实盘。

## 5. 第一次配置顺序

按以下顺序完成，避免来回验证和重复请求：

1. 在“系统设置”填写 PushPlus Token。
2. 配置 Steam Guard 的 `shared_secret`。
3. 如需自动确认上架，再配置 `identity_secret` 和设备信息。
4. 在“账号管理”添加 Steam 账号并完成登录。
5. 保存 Steam Cookie 后只验证一次。
6. 登录 BUFF 并保存 BUFF Cookie。
7. 查看“策略中心”，先使用保守策略。
8. 检查今日投入额度。
9. 确认订单台账没有待支付或待核对订单。
10. 再启动购买任务。

如果要使用 BUFF 余额自动付款，还要在“系统设置 -> Buff 支付”完成两项设置：

1. 支付方式选择“BUFF 可用资金（自动扣款）”或“智能：余额优先，不足转手动支付”。
2. 勾选“允许 BUFF 可用资金自动扣款”。未勾选时前端和后端都会拒绝启动余额任务。

严格余额模式：程序会先读取当前卖单的购买预览，只有名称确认为“BUFF可用资金”、按钮可点击、平台确认余额足够且返回余额不低于本笔金额时才锁单。余额不可用时跳过该商品，并继续尝试其他候选，不会自动改用支付宝或微信。

智能模式：余额足以覆盖整笔订单时使用 BUFF 可用资金；平台明确返回余额不足或当前订单不支持余额时，整笔改用设置中的微信或支付宝备用方式并等待人工付款。它不支持拆分付款。若余额预览超时、报错或状态不明确，程序不会猜测，也不会用备用方式锁单。

平台锁单成功后，程序先把订单号写入台账，再调用一次余额付款，并读取一次订单状态。付款调用不会自动重试；锁单或付款结果不明确时会立即停止整个任务并生成待核对订单。此时必须先到 BUFF 订单页核对，不能直接解除阻断或再次启动任务。

第一次实盘使用余额支付时，只保留少量余额、选择最低金额商品并全程看着 BUFF 订单页和运行日志；当前实现已通过离线模拟测试，但没有替用户执行真实自动扣款测试。

详细配置和第一次交易见 [02_账号配置与初次交易.md](02_账号配置与初次交易.md)。

## 6. 页面功能

### 仪表盘

显示运行状态、当前步骤、总投入、出售金额、收益、实际折扣比率、BUFF 可用资金、待付款提示和启动/停止按钮。

- `总投入`统计所有有效购买记录，包括仍在持有、等待入库、冷却中和已经售出的商品，不需要等商品售出后才出现。
- 出售金额、收益和实际折扣比率仍只使用已经填写售出价格的记录，未售商品不会被当成已实现收益。
- `BUFF 可用资金`来自最近一次经过严格名称识别的购买预览。任务进行余额预检时会自动更新；仪表盘每两秒读取的只是本地缓存，不会因此每两秒请求 BUFF。
- 如果某笔订单只返回“不可点击、带平台错误、余额 0.00”的支付通道，这个 `0.00`只代表该订单通道不可用，不会覆盖账号最近可信余额。余额卡片会保留旧值并显示“本次订单通道未采信”；真正购买仍会跳过该订单。
- 余额卡片右上角的刷新按钮会在任务停止时手动执行一次低频只读查询：先读取一个已知商品的当前卖单，再读取购买预览；它不会锁单或付款。任务运行时按钮请求会被后端拒绝，以免和购买流程竞争 BUFF 请求额度。
- 首次没有可信结果时显示“尚未读取”，不会用 `0.00`冒充真实余额。余额超过 15 分钟未重新核对时标为“缓存”；余额付款成功后先按本笔金额显示“付款后估算”，下一次预览会重新校准。

桌面界面默认缩放已从 `70%`调整为 `100%`。可在“系统设置 -> 系统参数 -> 界面缩放比例”选择 `70%`至 `140%`并保存，不需要每次用 `Ctrl + 鼠标滚轮`重新放大。

### 持有饰品

显示已购买但尚未售出的记录、购买价、购买时市场价、当前市场价和收益估算。

工具栏包含：

- `同步入库状态`：处理已有收货任务并更新订单和 `assetid`。它可能接受已有的 Steam 交易报价，但不会创建新购买或自动上架。
- `刷新商品现价`：批量获取当前 Steam 市场价并写入数据库。
- `刷新全部持有信息`：依次同步入库、刷新库存和刷新现价，避免并发重复请求。

### 操作记录与订单台账

订单台账保存 BUFF 平台订单号、商品、数量、金额、状态和错误说明，并显示：

- 今日投入额度。
- 今日已确认投入。
- 未决订单占用。
- 今日剩余额度。

如果存在待支付、用户已确认但平台状态未核对、或需要人工处理的订单，程序会阻止继续锁单。

只有在 BUFF 确认订单确实取消、未支付或已经退款后，才能点击“确认已取消”解除阻断。这个按钮只修改本地状态，不会取消 BUFF 平台订单。

如果原订单已经取消，但你后来在 BUFF 重新购买并完成付款，请使用“旧单取消，新单已付款”：

1. 填写新的 BUFF 平台订单号和实际成交单价。
2. 选择是否读取当前 Steam 市场价，作为补录时的“购入市场价”。这只是补录当下的参考值，不是原订单锁单时的历史快照。
3. 核对最终确认信息后提交。程序会在同一个数据库事务中取消旧单、登记新单并创建购买记录，避免只完成一半。
4. 新订单仍会计入今日投入和未决占用；重复的平台订单号会被拒绝。

收货状态现在分为“待卖家发送 Steam 报价”和“报价已发送，待在 Steam 接受”。如果你已经在 Steam 手动接受报价，再点击“同步入库状态”，程序会使用本次已读取的库存补全 `assetid`、入库时间和冷却时间，不会为此额外请求一次库存。同名同数量无法唯一匹配时不会猜测，需要人工核对。

### 库存

`刷新库存`会重新读取 Steam 库存、`assetid`、可交易状态和冷却时间。

手动刷新库存不会触发自动出售；按设置间隔执行的自动库存刷新仍可触发出售策略。

### 账号管理

保存 Steam 账号、Steam Cookie、BUFF Cookie，并执行账号验证。Cookie 有效只说明登录凭证可用，不代表市场接口一定没有限流。

### Steam 令牌

使用 `shared_secret` 生成快速变化的 Steam Guard 验证码。它不是 Cookie，也不是登录密码。

### 策略中心

管理买入筛选、价格稳定性、采购保护、出售条件和定价策略。第一次真实交易前不要大幅调整多个参数。

系统默认购入策略中包含“单件最高购买价”，默认 `50.00` 元。点开该模块可直接修改并保存；程序会以锁单前重新读取的 BUFF 实际卖单价校验，超出时不锁单。系统设置中的候选“最高价”只限制 SteamDT 查询范围，不能替代这项资金硬保护。

### 代理池

管理项目显式代理。当前代理池为空或关闭时，Steam 请求使用当前系统可用路由或本地 Steam 反向代理。不要为了“看起来更专业”随意导入大量公共代理。

### 运行日志

查看 `debug`、`info`、`warn` 和 `error`。日志区域支持鼠标选择和复制。提问时优先导出对应时间段日志，不要发送 Cookie 或 Token。

颜色含义：错误为红色、警告为黄色、普通信息为白色；只有最终选定购买对象、余额预览通过、锁单、付款、核销、入库、上架或售出等关键业务成功节点显示绿色。普通的数据拉取成功仍为白色，避免满屏绿色反而看不出真正成交节点。

每个实际买入轮次结束、进入 retry 前，会输出一组上下留白的彩色“轮次总结”。它只保留关键信息：筛选候选数、实际检查件次、成功订单和商品名、未通过原因分组、本轮投入、今日累计与剩余额度、最近可信 BUFF 余额，以及下一步动作。例如：

```text
━━━━ 任务 a1b2c3d4 · 第 2 轮总结 ━━━━
扫描　候选 25 件｜实际检查 7 件次
成功　2 单｜Item A ×2
未通过　5 件次｜价格/卖单/稳定性预检 4、BUFF 余额通道不可用 1
资金　本轮投入 ¥4.52｜今日累计 ¥9.02/20.00｜剩余额度 ¥10.98｜BUFF 最近可信 ¥15.11
下一步　300 秒后重新拉取
```

“件次”表示实际尝试次数：同一商品在不同订单或不同尝试中可能出现多次。成功商品会按名称合并显示数量，失败只按关键原因分组，不重复输出已经存在于详细日志中的长错误。

“导出日志”旁新增“导出轮次总结”。它保存当前程序日志生命周期内的全部轮次总结到 `log/round_summary_时间.txt`，不会因为普通运行日志超过 500 行被滚动淘汰而丢失早期轮次。点击“清空日志”也会同时清空待导出的轮次总结；关闭程序后应重新开始记录。

## 7. 每天的推荐操作

### 启动前

- 确认 Steam、BUFF 和 PushPlus 账号没有安全通知。
- 保持网络路径稳定，不要在任务运行中频繁换节点或切换多个网络工具。
- 确认今天计划投入多少。

### 启动后

1. 查看订单台账是否有未决订单。
2. 点击“同步入库状态”。
3. 点击“刷新商品现价”或“刷新全部持有信息”。
4. 检查今日剩余额度。
5. 查看当前启用的买入、出售策略。
6. 确认无异常后启动任务。

### 收到待付款通知

1. 核对商品名、单价、数量和总价。
2. 打开付款入口。
3. 完成付款。
4. 回到面板点击“已完成支付”。
5. 观察订单状态，不要重复启动另一个购买任务。

### 停止

优先点击页面“停止任务”，等待日志显示停止。需要完全退出时再关闭桌面窗口或命令行窗口。

## 9. 常见启动问题

### 页面打不开

检查端口：

```powershell
Get-NetTCPConnection -LocalPort 28472 -State Listen -ErrorAction SilentlyContinue
```

没有监听就重新运行启动脚本；有监听但页面打不开，先关闭旧实例再重启。

### 页面数据全部为零

依次确认：

- 后端进程仍在运行。
- 账号和 Cookie 已保存。
- 当前没有登录过期提示。
- 日志中没有数据库或接口错误。

### Playwright 找不到浏览器

```powershell
cd "D:\Vibe Coding\steam"
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD\.playwright"
.\.venv\Scripts\python.exe -m playwright install --list
```

### 日志显示 `waiting retry / retry in 300s`

表示本轮没有找到符合条件的饰品，或网络保护暂停了继续检查。不要因为等待就连续点击启动；先查看前一条 `warn` 或 `error`。

使用“BUFF 可用资金”或“余额优先”模式时，正常的候选重试倒计时结束后，程序会在下一轮拉取 SteamDT 数据前自动重新读取一次 BUFF 余额。它复用上一次购买预检保存的商品、卖单和价格，只调用一次只读购买预览，不会锁单或付款。因此，如果上一轮因余额不足跳过商品，收到通知后给 BUFF 充值即可继续等待，不需要停止和重启任务。

日志出现 `[Buff余额] Retry 结束已自动刷新`表示本轮已取得新余额；如果余额增加，会同时显示旧值和新值。若参考卖单已经失效、尚无完整参考信息或平台没有返回余额，程序只记录警告并继续下一轮，真正购买前仍会针对当时的卖单重新预检。

如果日志出现 `Retry 预览只返回订单级不可用通道 0.00，未覆盖最近可信余额`，说明参考订单不支持该支付通道，而不是确认账号余额已经归零。此时不要重复充值；可以在 BUFF 页面核对资金，程序会继续寻找其他候选。

`BUFF_RATE_LIMIT_PAUSED`这类平台限流保护等待，以及启动时间窗口等待，不会在倒计时结束时额外刷新余额。这是为了避免保护期刚结束就增加 BUFF 请求；它们与普通的“本轮无满足条件饰品，300 秒后重试”不同。

更完整的网络错误处理见 [03_网络与故障排查.md](03_网络与故障排查.md)。
