# 安装与日常使用

适用本次交付：Windows 10/11、本机使用、单个 AetherSwap 实例。命令均在 **PowerShell** 中运行。目录可以自己选择，不需要维护者的磁盘路径。

## 1. 安装前准备

- Git；安装后重新打开终端，运行 `git --version`。
- Python 3.11 x64；本次验收使用 3.11.5，源码要求至少 3.10。运行 `py -3.11 --version`。
- Edge 或 Chrome；Steam 与 BUFF 账号须由自己管理。
- 能访问 GitHub、Python 安装源及相关平台的网络。网页能打开不代表后台接口一定可用。

不要提供账号密码、Cookie 或手机令牌给维护者。不要从第三方获得一份“已经登录好的整套程序”。

## 2. 克隆正确的私有仓库

维护者先邀请你的 GitHub 账号，你接受后再操作。在自己选定的父目录打开 PowerShell：

```powershell
git clone https://github.com/aAd1oS/AetherSwap-working-backup.git AetherSwap
cd AetherSwap
git rev-parse --short HEAD
```

将最后一行的提交号与维护者给出的交付提交号核对。文件夹名不是版本号；目前 GitHub 旧提交不自动等于本地新交付稿。

- 提示 Repository not found：先确认已接受邀请、Git 使用的是获邀账号，不要改克隆原作者仓库。
- 使用 Git 的登录提示完成认证，不把 Token 拼进地址或发给别人。
- 提示目录已存在：不要覆盖旧运行目录，另选空目录。
- 仅遇到 Windows Git TLS 的 `SEC_E_NO_CREDENTIALS` 时，可对本次克隆加 `git -c http.sslBackend=openssl clone ...`；不要关闭证书校验。

## 3. 安装依赖

在刚克隆的项目根目录执行；不需要激活脚本，也不需要调整 PowerShell 执行策略：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) ".playwright"
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -m pip check
```

每一步成功后再执行下一步。最后应显示 `No broken requirements found.`。仅安装系统 Chrome/Edge 不能替代 Playwright 的 Chromium 安装。

普通使用不需要 Node.js、pytest、Docker、SteamDT 开放平台 Key 或付费行情 API；某个可选功能明确要求 Key 时再单独配置。不要把此前模拟实验的数据商要求当成运行主项目的前置条件。

依赖当前使用最低版本约束，并非锁定的可复现发行包；未来安装结果若变化，应保留报错并联系维护者，不宣称任意新版 Python 都经过验证。

## 4. 第一次启动：先看空白界面

先阅读根目录的风险说明。首次建议从终端启动，确保能看到报错和确认提示：

```powershell
$env:AETHERSWAP_MODE = "desktop"
$env:AETHERSWAP_HOST = "127.0.0.1"
$env:AETHERSWAP_PORT = "28472"
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) ".playwright"
.\.venv\Scripts\python.exe run.py
```

按提示确认后，窗口或浏览器应打开；否则手动访问 `http://127.0.0.1:28472/`。内嵌窗口不可用时可以使用外部浏览器，不要同时再启动另一个实例。

另开 PowerShell 可只读检查：

```powershell
Invoke-RestMethod http://127.0.0.1:28472/api/runtime
```

空白验收：

- 页面可打开，接口返回 `ok: True`。
- 没有维护者的账号、持仓和订单；如出现，立即停止，不要操作。
- 未启动购买任务。
- 出售策略保持暂停；余额自动扣款、自动出售、自动确认不启用。
- 程序没有持续重复的启动异常。

**首页能打开不等于平台已登录，也不等于真实交易已验证。** 新克隆应使用源码默认配置，不能导入维护者的完整导出。

## 5. 以后启动与完整退出

日常可双击 `start-aetherswap-desktop.cmd`。它使用项目自己的 .venv 和 .playwright，固定本地端口，并清理继承的代理环境变量。该启动器会自动接受免责声明，因此应在首次手动阅读后使用。

备用：`start-aetherswap-server.cmd` 只运行本地后台，再自己打开浏览器。它不是“无副作用演示模式”，也不是公网服务器部署教程。

停止步骤：

1. 停止购买任务，核对待支付、付款未知和待确认订单；停止程序不会取消平台订单。
2. 如需停止全部后台活动，在启动终端按 Ctrl+C，并等到进程退出。
3. 仅关网页或桌面窗口不保证停止后台；仅停止购买也不保证在售、收货等后台任务全部停止。
4. 再访问本地页面应不可用。仍可访问时先找已有实例，不要重复启动或随意结束其他 Python 进程。

不要把面板暴露到局域网或公网，不要把绑定地址改为 `0.0.0.0`。现有 Docker 默认端口映射也不属于本次安全交付路径。

## 6. 第一次配置顺序

先阅读 [账号配置与首次交易](02_账号配置与首次交易.md)：

1. 添加自己的 Steam 账号并设为当前账号。
2. 更新 Steam 信息，只验证一次，核对身份与钱包币种。
3. 配置对应的 BUFF 登录信息，只读核对。
4. 按实际需要配置通知；自动确认密钥不是浏览空白界面的必要条件。
5. 在策略中心确认实际启用的模块、单件上限和投入额度；默认数值不是为你定制的安全预算。
6. 所有检查完成后，再自行决定是否开展一次小额真实交易。

不启用余额自动扣款来“试一下”；不通过关闭保护来追求必须买到商品。

## 7. 页面与日常操作

| 页面 | 用途与注意事项 |
|---|---|
| 仪表盘 | 状态、预算、开始/停止购买；开始会进入真实交易流程 |
| 操作记录/订单台账 | 核对未决订单、人工处理；本地取消不代表平台取消 |
| AetherSwap 交易持仓 | 成本、上架价格、现价与状态；同步入库可能接收已存在报价 |
| Steam 库存 | 真实资产、冷却与归属；先确认个人资产未被托管 |
| 账号管理 | 登录、凭据和当前身份；切换前结束账号操作 |
| 策略中心 | 购入、出售条件与模拟判定；不是完整历史回测 |
| 系统设置/代理池 | 自动化授权、通知与网络路径 |
| 日志 | 排查依据；只分享脱敏的相关片段 |

每日顺序：确认账号和网络 → 查看未决订单 → 检查预算、自动出售及授权 → 必要时只刷新一次 → 再决定启动购买。

未知订单、身份不一致、连续网络错误时停止。没有合适商品是允许的结果。

## 8. 更新与排错

更新前完整退出，并私下备份自己的数据；具体见 [交付与维护](06_协作与审查.md)。不要运行“出厂重置”来更新或准备分享，它可能删除真实记录。

- 缺 Python/依赖：确认正在使用项目 .venv。
- 缺浏览器：重新执行第 3 节的浏览器目录设置和安装。
- 端口占用：先检查已有 AetherSwap，不开多个实例。
- 私有仓库无法访问：确认邀请和 GitHub 登录。
- 登录、证书、429、超时：按 [故障排查](03_网络与故障排查.md) 逐项处理。
