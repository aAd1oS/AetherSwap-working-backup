# 价格、支付与策略

本文统一解释价格口径、支付行为和策略边界。任何策略都不能绕过账户配置、安全校验和人工确认。

## 使用策略中心

购入与出售条件在“策略中心”设置；通知、网络和全局授权在“系统设置”设置。先查看当前启用的策略，不假定新克隆带有维护者的自定义策略。

- 系统预设的结构只读；调整模块顺序、增删或启用状态时先复制为自定义策略。
- 参数保存、模块依赖与启用条件须通过界面校验，启用前查看差异并进行“模拟运行”。
- “模拟运行”是模块判定与动作跳过检查，不真实下单，不代表已经进行历史回测，也不能证明 24 小时内能成交。
- 用户模块采用声明式条件；外部代码、命令或任意脚本不属于可执行策略插件。
- 不熟悉时保持出售暂停和自动出售关闭，再逐项理解参数。不要为了买满预算关闭保护。

完整虚拟交易研究仍暂停，见 [暂停交接](archive/2026-09-08_虚拟交易模拟计划与暂停交接.md)，不是本次已经交付的功能。

## 1. 价格口径

| 名称 | 含义 |
|---|---|
| 采购价 | 实际买入单价 |
| 采购市场价 | 采购时用于比较的市场参考价 |
| 当前市场价 | 当前时点重新取得的参考价 |
| 预计卖出毛价 | 尚未扣除手续费的挂牌或成交估计 |
| 预计卖出净价 | 扣除平台手续费后的到账估计；只有明确知道费率时才计算 |
| 价格比 | 候选采购价相对参考价的比例 |
| 理论回款 | 基于价格和费率计算的估计，不等于真实成交到账 |

不同接口可能返回毛价、净价或币种不明确的数字。字段语义没有被真实样本证实时，界面和日志必须保留“估计”字样，不能用经验公式伪装成事实。

项目中有两个容易混淆的上限：

- SteamDT 候选价格上限用于限制外部候选来源。
- 策略单件采购上限用于限制实际购买决策。

前者不能替代后者；两者都应保持保守。

## 2. 支付模式

### 手动支付

系统创建购买尝试并打开或提示支付入口，由用户完成付款。未取得平台终态前，订单保持待确认，不自动重复创建购买。

当前界面提供支付宝和微信选项，不再是旧 README 所称的“仅微信”。平台是否支持当前账号及具体订单，以实际返回为准；邮件通知仅作辅助，不能代替平台状态。

### 余额支付

只有在余额、账户匹配和购买结果都明确时才允许继续。余额不足、接口不可用、响应无法识别时应停止，而不是退化成猜测成功。

还必须启用“允许 BUFF 可用资金自动扣款”独立授权。该授权默认关闭，首次使用不要启用。

### 智能支付

优先使用明确可用的余额路径；明确余额不足时整笔转人工支付，不拆分付款。余额查询或扣款结果未知时停止核对，不再创建备用订单。任何支付副作用最多触发一次，后续只做查询和对账。

共同原则：未知即停止、失败不循环、页面打开不等于支付成功、日志不得记录凭据。

## 3. 当前采购策略

策略会综合价格比例、预算、单件上限、账户、库存和风险状态筛选候选。当前默认购入策略中的最高折扣、卖压、历史数据窗口、IQR 历史异常值清洗、CV 波动率、R²/斜率趋势质量、价格分位与均线位置、单件金额、采购数量、流动性仓位、低价惩罚、同名持仓和目标余额都已接入运行时；模块被启用时会实际限制候选或采购数量。MAD、Theil-Sen 斜率、Spearman 和高点持续度仍是影子指标，只用于观察，不参与放行或拒绝。

“系统参数 → 输出策略模块判定日志”默认关闭。开启后会额外输出 `模块 id + PASS/REJECT/UNAVAILABLE/DATA + 观测值与阈值`；关闭只减少解释日志，不会关闭任何策略或安全检查。卖压模块启用但日销量或 Steam 卖单深度缺失时失败关闭，不再把数据缺失当作通过。

“历史异常值清洗（IQR）”位于历史数据窗口之后，默认参数为 IQR 倍数 `1.5`、最大异常占比 `0.2`，并保护近期持续变动：

- 孤立异常成交会连同时间和成交量一起移除，清洗后的同一组记录统一进入均价、VWAP、CV、每日曲线、EMA、斜率、R² 和价格分位计算。
- 最近连续三天的日均价都在同一侧越过 IQR 边界时，视为可能的市场换挡；不删除这些记录，直接暂停该候选购入。
- 检出的异常记录占比超过配置上限时，不强行生成平滑结论，直接暂停该候选购入。
- 输出保留原始数量、使用数量、异常及实际移除数量、比例、上下界、持续变动标记和 PASS/REJECT 原因，便于审计。
- 系统默认购入策略启用该模块；没有此模块的既有自定义策略继续使用旧计算路径。关闭模块不会移除原来已用于均价、CV 和分位的基础 IQR 行为。

建议配置遵循四条原则：

1. 先限制总预算，再限制单件金额。
2. 先以少量样本验证字段和订单状态，再扩大规模。
3. 不设置“必须花完”的目标。
4. 外部行情缺失、异常或币种不明时跳过候选。

## 4. 出售和持有

商品进入可交易状态后，系统可以提出继续持有、改价或出售建议。设置中的“开启上架分段自动模式策略”默认关闭：关闭时保持原有 24 小时复评；开启后按当前连续上架时长采用以下门槛：

- 0～24 小时不触发滞销改价。
- 24～48 小时：预计仍需等待至少 72 小时时，才允许当前出售策略提出的降价进入下架重挂。
- 48～72 小时：预计仍需等待至少 48 小时时，才允许降价。
- 72 小时及以后：预计仍需等待至少 24 小时时，才允许降价。
- 分段时间只触发复评，不能绕过当前出售策略、账户身份、自动出售授权、币种、利润保护和 Steam 会话检查。
- 缺少可靠成交量时禁止自动降价；滞销挂单也不会被自动上调。
- 下架成功后必须唯一确认新 asset id，才会交回当前出售策略重新上架；不能唯一确认时停止自动重挂。
- 重新上架视为新的连续上架周期，重新等待 24 小时，避免短时间连续调价。
- 到达首次复评时间后每 10 分钟重新计算；下架失败保留本地在售状态并在 1 小时后重试。
- 相同建议不重复通知；价格目标或建议状态变化时才通知。
- 缺少成交量和深度信息时，不把短时价差当作稳定流动性。

C5 目前只作为只读比价与人工建议来源，不代表已经接入自动下单、自动支付或自动出售。

## 5. 箱子策略结论

历史研究支持的只是“小额、分散、可停止”的实验，不支持保证收益，也不支持把预算机械花完。箱子策略不是默认主策略；启用前仍须验证手续费、锁定期、成交深度和实际到账。

## 6. 修改策略前的最低验证

每次调整阈值或支付逻辑，至少验证：配置解析、候选过滤、预算边界、重复执行、未知响应、订单持久化和通知去重。涉及真实资金的结果必须另列“待真实平台样本验证”，不能用离线测试替代。
