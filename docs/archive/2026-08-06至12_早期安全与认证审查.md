# 2026-08-06 至 12：早期安全与认证审查

## 背景

项目早期围绕凭据存储、JWT、服务暴露和平台认证进行了多轮检查。这些报告促成了后续的失败关闭、凭据脱敏和网络诊断边界。

## 保留结论

- Cookie、API key、共享密钥和通知令牌不能写入仓库、日志或审查提示词。
- JWT 只能解决令牌校验的一部分，不能替代授权、CSRF、防重放、限流和 TLS。
- 服务监听非回环地址属于部署边界变化，必须先完成应用层保护。
- Steam 的 403、登录失败或 Cookie 不可用不一定是凭据失效；本地代理、hosts、DNS、系统时间和证书链应先排查。
- `valid`、`invalid`、`rate_limited` 和 `unavailable` 等状态必须区分，限流或不可用不能触发重复登录循环。
- 认证诊断应有次数和时间上限，不能用无限重试掩盖真实故障。

## 后续影响

这些原则现已进入 [网络与故障排查](../03_网络与故障排查.md) 和 [维护、安全与路线图](../05_维护安全与路线图.md)。归档不证明当前实现已覆盖所有 Web 安全项，尤其是非回环部署仍属于待完成工作。
