# AetherSwap 初次交易建议步骤

适用目录：`D:\ai thinking\steam`

本文件给第一次使用 AetherSwap 做交易的人看。它不是“赚钱教程”，也不是投资建议，只是一份尽量保守的操作顺序，目标是：

- 先把账号、网络、令牌、Cookie、代理、日志这些基础东西跑通。
- 先小额验证流程，不要一上来大额自动化。
- 遇到问题知道该看哪里、该停哪里。
- 尽量避免因为配置不懂、网络不稳、策略太激进导致账号或资产出问题。

参考：

- 项目 README：`D:\ai thinking\steam\README.md`
- Steam 官方交易与市场限制说明：`https://help.steampowered.com/en/faqs/view/451E-96B3-D194-50FC`

> 所有 Steam / Buff / 市场规则都可能变化，最终以 Steam、Buff 页面上的实时提示为准。

## 1. 初次交易前先想清楚

### 你要先接受这些风险

AetherSwap 会涉及：

- Steam 账号登录
- Buff 账号登录
- Cookie
- Steam 移动令牌密钥
- 自动购买
- 自动上架
- 交易确认
- 代理网络
- 本地数据库记录

风险包括：

- Steam 或 Buff 风控。
- Cookie 泄露。
- 令牌密钥泄露。
- 买入后价格下跌。
- 买入后卖不出去。
- 上架价格不理想。
- 网络卡住导致流程中断。
- 自动化行为不符合平台规则。

所以第一次不要追求收益，第一次只验证流程。

### 第一次交易的目标

第一次交易只做三件事：

1. 验证账号能登录。
2. 验证程序能读库存、读行情、写日志。
3. 用最小金额验证一次完整链路。

不要把第一次交易当成赚钱任务。

### 第一次交易建议规模

建议：

- 用测试账号或低风险账号。
- 用小金额。
- 只做 1 件或极少量物品。
- 保留默认保守策略。
- 全程盯着页面和日志。
- 不要挂机离开。

不建议：

- 直接使用主号。
- 直接大额余额。
- 一次买很多。
- 先改激进策略。
- 使用来路不明的代理。
- 边不懂边开自动任务。

## 4. 第 1 步：确认网络

初次交易前先不要急着填账号。先确认普通浏览器能打开这些页面：

```text
https://steamcommunity.com
https://store.steampowered.com
https://buff.163.com
```

如果打不开或很慢：

- 开 Steam 加速器。
- 换节点。
- 换网络。
- 暂时不要做交易。

### 网络为什么重要

交易流程里会频繁访问：

- Steam 登录
- Steam 社区库存
- Steam 市场
- Steam Guard 确认
- Buff 页面 / 接口
- 行情数据

网络不稳定时容易出现：

- 登录失败
- Cookie 提取失败
- 库存读取不到
- 价格读取不到
- 付款后状态没同步
- 上架确认失败

第一次交易宁可慢，不要在网络抽风时硬跑。

## 5. 第 2 步：准备账号

### Steam 账号建议

第一次建议用低风险账号。

账号最好满足：

- 能正常登录 Steam。
- 能正常打开 Steam 社区。
- 能正常查看库存。
- 已启用 Steam Guard。
- 没有明显市场或交易限制。
- 没有异常风控提示。

如果 Steam 页面提示账号暂时不能交易、不能使用市场、需要等待、需要验证，请以 Steam 页面为准。不要试图绕过。

### Buff 账号建议

Buff 账号最好满足：

- 能正常登录。
- 能正常浏览商品。
- 能正常查看订单。
- 支付方式可用。
- 没有安全验证异常。

项目 README 里写当前购买结账主要使用微信支付。第一次最好走手动确认，不要一开始追求全自动。

## 6. 第 3 步：配置 Steam 令牌

进入页面：

```text
系统设置 / Steam 令牌
```

你可能会看到这些字段：

```text
shared_secret
identity_secret
```

简单理解：

- `shared_secret`：生成 Steam 两步验证码。
- `identity_secret`：确认交易、上架等动作。

### 填写建议

1. 先确认来源可靠。
2. 手动复制时不要多空格。
3. 填完后保存。
4. 去【Steam 令牌】页面验证能否生成验证码。
5. 如果验证码不对，先停，不要继续绑定交易。

### 绝对不要做

不要把这些发给别人：

```text
shared_secret
identity_secret
Steam Cookie
Buff Cookie
邮箱授权码
```

这些信息泄露后可能导致账号或资产风险。

## 7. 第 4 步：绑定 Steam 账号

进入：

```text
账号管理
```

建议顺序：

1. 添加 Steam 账号。
2. 尝试自动登录或验证。
3. 如果需要验证码，用 Steam 令牌生成。
4. 登录成功后观察账号状态。
5. 检查能否读取库存。

### 成功的表现

一般会看到：

- 账号状态正常。
- 没有明显登录失败提示。
- 库存能读取。
- 运行日志没有连续报 Steam 登录错误。

### 失败时先查这些

1. 普通浏览器能不能登录 Steam。
2. Steam 加速器有没有开。
3. 账号是否触发验证码、人机验证、邮箱验证。
4. Cookie 是否过期。
5. 代理是否配置错。

### 自动登录失败怎么办

可以先不要硬调自动登录。更稳的排查顺序：

1. 普通浏览器登录 Steam。
2. 确认 Steam 社区能打开。
3. 回 AetherSwap 重新验证账号。
4. 仍失败时再考虑手动 Cookie。

手动 Cookie 属于敏感操作，复制后不要发给别人。

如果 Buff 状态异常：

- 检查 Cookie 是否过期。
- 检查是否需要重新登录。
- 检查是否被风控要求验证。
- 检查网络是否能稳定访问 Buff。

## 9. 第 6 步：配置通知

通知不是必须，但第一次交易建议至少开一种。

常见通知：

- PushPlus 微信推送
- 邮件通知

通知能帮你及时知道：

- 订单创建
- 等待付款
- 付款超时
- 库存入库
- 上架成功
- 上架失败
- 任务异常

如果你不配置通知，就要自己一直盯着页面。

## 10. 第 7 步：邮箱 IMAP 是否要配置

项目 README 里说明了付款确认有两种模式：

### 模式 A：不配置邮箱

程序会降级为手动确认。

适合第一次交易。

流程大概是：

1. 程序生成订单或支付信息。
2. 你手动完成付款。
3. 回页面点击“已支付”或类似确认按钮。
4. 程序继续后续流程。

优点：

- 好理解。
- 风险低。
- 出问题时容易知道卡在哪。

缺点：

- 需要你盯着。
- 超时可能导致订单跳过。

### 模式 B：配置邮箱 IMAP

程序监听付款通知邮件，自动识别付款状态。

适合你已经理解流程后再开。

第一次不建议一上来就配邮箱自动化。

## 11. 第 8 步：代理怎么选

第一次交易建议先用稳定网络，不要上来就堆代理池。

### 可以先用

- Steam 加速器
- 稳定的本地代理
- 你自己信任的代理

### 不建议

- 免费公开代理
- 来路不明的代理池
- 群里别人发的代理
- 大量轮换且不稳定的代理

原因很简单：代理可能看到你的请求，坏代理也可能让登录和 Cookie 流程变得更危险。

## 12. 第 9 步：先看默认策略，不要急着改

进入：

```text
策略中心
```

你会看到：

- 购入策略
- 出售策略
- 模块管理

第一次建议：

1. 只看，不乱改。
2. 使用默认策略。
3. 如果必须改，先复制策略再改。
4. 改完一定先模拟运行。

### 默认策略为什么保守

默认策略会尽量过滤掉：

- 价格波动大的物品
- 趋势不稳定的物品
- 成交量不理想的物品
- 卖压不舒服的物品
- 折扣不够的物品

保守不是坏事。第一次目标是跑通流程。

## 13. 第 10 步：设置第一次交易的安全边界

第一次交易前，建议你给自己定几个硬规则。

### 金额边界

建议：

```text
只用能接受亏损的小金额。
```

不要借钱，不要大额，不要用生活费。

### 数量边界

建议：

```text
第一次只验证 1 个物品或极少量物品。
```

不要一上来批量买。

### 时间边界

建议：

```text
第一次全程盯着，不挂机。
```

如果你接下来没空，就先不要开始交易。

### 风险边界

出现这些情况就停：

- Steam 登录反复失败。
- Buff 登录反复失败。
- Cookie 状态异常。
- 网络明显不稳定。
- 价格数据拉不到。
- 页面一直报错。
- 你看不懂当前流程卡在哪。


## 15. 第 12 步：第一次购入建议流程

进入首页或任务页面。

### 建议做法

1. 打开【运行日志】。
2. 打开【策略中心】，确认当前启用的是默认购入策略。
3. 回到首页。
4. 点击启动任务。
5. 观察日志，不要离开。

你要重点看：

- 是否正常拉取候选商品。
- 是否正常读取 Steam / Buff 价格。
- 是否有大量网络错误。
- 是否有登录状态错误。
- 是否创建订单。
- 是否进入等待付款。

### 付款环节

第一次建议手动付款和手动确认。

流程可能类似：

1. 程序创建订单。
2. 页面提示付款。
3. 你确认金额、商品、平台都没问题。
4. 手动扫码或按提示付款。
5. 回到页面点击已支付 / 确认付款。
6. 观察后续日志。

付款前一定核对：

```text
商品是否对
金额是否对
平台是否对
账号是否对
```

不对就不要付款。

### 付款后

付款后观察：

- Buff 订单状态。
- AetherSwap 日志。
- Steam 库存是否有变化。
- 是否提示等待发货。
- 是否出现超时。

如果付款成功但程序没识别：

1. 不要重复付款。
2. 看 Buff 订单状态。
3. 看 AetherSwap 运行日志。
4. 必要时手动确认。
5. 仍异常就暂停任务。

## 16. 第 13 步：入库后不要急着卖

Steam 饰品交易和市场可能存在限制、冷却期或确认要求。不同物品、不同账号、不同平台提示可能不同。

你要以 Steam 页面实际提示为准。

建议：

1. 在 Steam 库存里确认物品是否到账。
2. 看物品是否可交易 / 可出售。
3. 如果 Steam 显示需要等待，就等待。
4. 不要试图绕过平台限制。

AetherSwap 的自动化也应当服从平台状态。

## 17. 第 14 步：第一次上架建议流程

第一次上架也建议小心。

### 上架前检查

确认：

```text
[ ] 物品已在 Steam 库存
[ ] 物品可出售或已到可出售时间
[ ] Steam 令牌确认可用
[ ] identity_secret 正常
[ ] 出售策略仍是默认或保守策略
[ ] 当前网络稳定
```

### 上架时观察

重点看：

- 程序是否识别库存。
- 是否计算上架价格。
- 是否触发 Steam Guard 确认。
- 是否上架成功。
- 是否写入上架记录。

如果上架价格看起来明显不合理，停。

不要为了“赶紧卖出”盲目降低价格。

## 18. 第 15 步：成交后检查

如果物品成交，检查这些地方：

1. Steam 余额是否变化。
2. AetherSwap 操作记录是否写入。
3. 上架记录是否更新。
4. 数据分析是否出现记录。
5. 实际折扣比率是否符合预期。

第一次成交后，先不要马上扩大规模。

建议复盘：

- 买入用了多久。
- 入库用了多久。
- 等待了多久。
- 上架价格是否合理。
- 成交是否顺利。
- 中间有没有错误日志。
- 实际收益 / 折扣是否符合预期。

## 19. 第一次交易失败怎么办

失败很正常。不要连续猛点、不要重复付款。

### 如果卡在登录

处理：

1. 停止任务。
2. 普通浏览器确认 Steam / Buff 能登录。
3. 重新登录或刷新 Cookie。
4. 再验证账号状态。

### 如果卡在付款

处理：

1. 先确认有没有真的付款。
2. 如果未付款，取消或等待订单超时。
3. 如果已付款，不要重复付款。
4. 看 Buff 订单状态。
5. 手动确认或联系客服，以平台订单为准。

### 如果卡在入库

处理：

1. 看 Buff 是否显示发货。
2. 看 Steam 库存是否到账。
3. 看 Steam 是否需要确认。
4. 刷新库存。
5. 看运行日志。

### 如果卡在上架

处理：

1. 看 Steam 是否允许出售。
2. 看 Steam Guard 是否正常。
3. 看 identity_secret 是否正确。
4. 看是否网络失败。
5. 手动去 Steam 页面检查。

### 如果价格异常

处理：

1. 停止任务。
2. 不要继续自动买卖。
3. 检查策略参数。
4. 检查行情数据来源。
5. 小范围模拟运行。

## 20. 第一次交易后再考虑自动化

第一次成功后，也不要马上全自动大额挂机。

建议分阶段：

### 阶段 1：手动盯流程

- 手动确认付款。
- 手动观察日志。
- 少量物品。

### 阶段 2：半自动

- 开通知。
- 可选配置邮箱 IMAP。
- 仍然限制金额和数量。

### 阶段 3：低风险自动

- 小额预算。
- 保守策略。
- 稳定代理。
- 定期看日志。

### 阶段 4：扩大规模

只有在你已经理解这些内容后再考虑：

- 策略参数含义。
- 平台限制。
- 失败处理。
- Cookie 更新。
- 代理质量。
- 交易亏损风险。

## 21. 新手最容易犯的错误

### 错误 1：没看懂就启动任务

先熟悉页面，再操作。

### 错误 2：网络不稳还硬跑

Steam / Buff 网络不稳时，交易流程很容易断。

### 错误 3：把密钥发给别人看

`shared_secret`、`identity_secret`、Cookie 都是敏感信息。

### 错误 4：一开始就改激进策略

默认保守策略不是摆设。第一次先跑通流程。

### 错误 5：付款后没等状态同步，又重复操作

付款相关问题先看平台订单，不要重复付款。

### 错误 6：把管理面板暴露公网

`127.0.0.1` 是本机访问。服务器部署时不要裸露端口。

### 错误 7：不知道怎么停

出问题时先停任务，必要时关闭服务窗口。

如果前面都稳定：

- 做第一次小额购入。
- 手动付款。
- 盯日志。
- 确认入库。

### 后续

- 小额上架。
- 观察成交。
- 复盘记录。
